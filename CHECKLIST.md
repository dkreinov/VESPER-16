# Is this Skill worth keeping?

Use judgment. A clear request, project note, reference, or script may already be enough. Match the checking effort to how widely the Skill will be reused and how much people will rely on it.

## For a personal Skill: quick checks

You usually do not need a benchmark for a lightweight personal Skill.

- [ ] **Search before building.** Try a clear prompt first. If reusable guidance is still needed, look for an existing Skill and check it before creating another.
- [ ] **Name the gap.** What knowledge, procedure, or repeated explanation does this save?
- [ ] **Read it critically.** Check important facts, commands, and supporting files. Remove instructions that do not fit your work.
- [ ] **Try it and inspect the result.** Did it help with a real task? The agent saying “done” is not a check.
- [ ] **Use the simpler option when it works.** Keep the Skill if it saves useful work. Otherwise revise, simplify, or remove it.

## For a shared, frequently used Skill: stronger evidence

When many people will rely on the same Skill repeatedly, invest in representative tasks and fair comparisons. The checks below describe that deeper evaluation; they are not mandatory steps for every personal Skill.

- [ ] **Define success.** Choose a result you can check, representative tasks, and suitable limits before starting.
- [ ] **Save checked knowledge.** Verify important rules and commands against the real system, including supporting files. Keep reusable steps and their limits. Leave answers to your test tasks out of the package.
- [ ] **Compare fairly.** Try with and without the Skill, and consider a simpler alternative. Match the model, effort, tools, starting files, and limits. Use fresh agents or chats and clean project copies. Record or disable memory and keep previous answers out of reach.
- [ ] **Check that the guidance was used.** Inspect the available run history or file-read trace. Mark this “unknown” if you cannot verify it. A file being present is not enough.
- [ ] **Test transfer.** Use a new task kept out of writing, revising, and selecting the Skill. Include fresh users or agents where practical.
- [ ] **Check actual outputs and repeat as needed.** Run tests or inspect required behavior. Choose the repeat count before running a comparison. Keep failures and timeouts, not only successful examples.
- [ ] **Count the whole effort.** Record quality, elapsed time, cost or its estimate, and human help. Include creation, checking, and maintenance. Mark missing values “unknown.”
- [ ] **Make a decision.** Keep the Skill when the benefit justifies the total work. Otherwise improve and retest, simplify or remove it, or gather more evidence. “No clear benefit” is a useful result.

## For all Skills: occasional cleanup

- [ ] Remove stale facts, obsolete steps, duplicated rules, and unused resources.
- [ ] Keep the useful guidance clear and easy to find.
- [ ] Recheck important behavior after relevant changes to the model, tools, task, or Skill. Scale the recheck to the change.

**Correct? Reusable? Worth it? Ask the questions; scale the effort.**
