# Is this Skill worth keeping?

Use this on a repeated task. A short prompt, project note, or script may already be enough. “No clear benefit” is a useful result.

| In our lesson | What to test |
| --- | --- |
| [T3 — Squash](https://github.com/dkreinov/VESPER-16/blob/main/tasks/T3.md) | Capture experience from the first attempt. The later T3 with/without pair tests reuse on the same task. |
| [T6 — Nameplate and moving ball](https://github.com/dkreinov/VESPER-16/blob/main/tasks/T6.md) | Compare fresh agents with and without the Skill on a different task using the same console. |
| [T4 — Breakout](https://github.com/dkreinov/VESPER-16/blob/main/tasks/T4.md) | The harder example from the talk and optional homework. Test the frozen Skill on it with a matched control. |

Use the **Phase 3 pairs** to measure what the Skill adds. Phase 1 and Phase 3 use different models and limits. A task is held out only if it was not used to write, revise, or select that Skill.

- [ ] **Name the need and define success.** What does the agent keep having to rediscover? Before running anything, choose a result you can check and a time limit.

- [ ] **Save checked knowledge.** Verify important rules and commands against the real system, including supporting files. Keep reusable steps and their limits. Leave answers to your test tasks out of the package.

- [ ] **Compare fairly.** Try the same task with and without the Skill. Use fresh chats and clean project copies. Match the model, effort, tools, starting files, and limits. Disable memory or record what it supplies. Keep previous answers out of reach.

- [ ] **Check that the agent read it.** Look in the available run history or file-read trace. Mark this “unknown” if you cannot verify it. A file being present is not enough.

- [ ] **Try a new task.** Use a task you kept out of writing and revising the Skill. Check whether the saved knowledge helps beyond the original answer.

- [ ] **Check the actual output.** Run tests or inspect the required behavior yourself. The agent saying “done” is not a check.

- [ ] **Repeat and record every attempt.** Choose the repeat count before starting. Record quality, on-time completion, elapsed time, and cost or its estimate. Keep failures and timeouts. Mark missing values “unknown.” Count creation, checking, and maintenance as extra work.

- [ ] **Make a decision.** Keep it when the benefit justifies the total work. Otherwise improve and retest, simplify or remove it, or gather more evidence. Recheck after a relevant model, tool, task, or Skill change.
