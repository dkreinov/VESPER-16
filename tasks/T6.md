# T6 — Nameplate (your name and a bouncing ball)

Using the VESPER-16 dev kit in this folder (`bin/vesper`), write a small program that shows the
name **{NAME}** at the top of the screen, with a ball bouncing below it that you can steer.
All positions below are as they appear in the PNG frames (column 0 = left, row 0 = **top**).
The screen is 64 columns by 48 rows.

**Screen**
- Black (`#000000`) background.
- **Name:** white (`#FFFFFF`) pixels. The letters use a fixed 3x5 font, one blank column between
  letters. The top-left pixel of the first letter is at **column 1, row 1**, so the name fills
  rows 1–5. The picture below is 1:1 (`#` = white pixel, `.` = black). Its first character is
  column 1, its first line is row 1:

```
{NAME_ROWS}
```

- **Separator:** row 7, columns 0–63, all green (`#3CD25A`).
- **Field:** rows 8–47 (below the separator).
- **Ball:** a 2×2 block of sky blue (`#3FA9F5`) inside the field. Its top-left pixel starts at
  **column 31, row 26**.
- Nothing else is ever drawn. The name and the separator never change.

**Ball movement** — in every frame after frame 0, in this order:
1. Read the buttons once. If **UP** is held (and DOWN is not), the vertical direction becomes
   *up* (towards row 0). If **DOWN** is held (and UP is not), it becomes *down*. If both or neither
   are held, the vertical direction stays as it was.
2. The ball moves 1 pixel horizontally and 1 pixel vertically in its current directions. At the
   start the directions are *right* (+1 column) and *down* (+1 row).
3. **Bounce:** the ball's top-left pixel must stay within columns 0–62 and rows 8–46. If the move
   would take it outside on one axis (column < 0, column > 62, row < 8 or row > 46), that axis
   direction is reversed and the ball moves 1 pixel in the new direction instead, so it never
   leaves the field. Each axis is checked on its own; in a corner both can bounce in the same frame.
4. The picture is drawn.

Frame 0 (`frame_0000.png`) shows the start position, before any move.

*Example.* The ball is at column 62, row 20, moving right and down, and no button is held. In the
next frame the column would become 63, which is outside, so the horizontal direction turns to
*left* and the column becomes 61. The row becomes 21 as usual. The ball is now at (61, 21).
*Second example.* The ball is at column 10, row 8, moving down, and UP is held. The direction turns
to *up*; row 7 would be outside, so the direction turns back to *down* and the row becomes 9.

Buttons are supplied with `--input`. Save the program as `solutions/T6.vsa`. It
must run with e.g.

```
bin/vesper run solutions/T6.vsa --frames 300 --input keys.txt --out out/T6
```

and print `OK 300 frames`. We will play-test it with our own key sequences (UP, DOWN, both, none,
long holds, every wall and corner), so try several input files yourself and check the frames before
you say you're done.
