# T3 — Squash (one-player Pong against the wall)

Using the VESPER-16 dev kit in this folder (`bin/vesper`), write a small playable squash game.
All positions below are as they appear in the PNG frames (column 0 = left, row 0 = **top**).

**Screen**
- Black (`#000000`) background.
- **Score bar:** the top row (row 0) shows the score as one green (`#3CD25A`) pixel per point,
  starting at column 0 and growing to the right (score 3 = columns 0, 1, 2 green). Score 0 = an
  empty top row. Nothing else is ever drawn in row 0.
- **Paddle:** sky blue (`#3FA9F5`), 1 pixel wide and 8 pixels tall, in **column 1**. It starts
  roughly vertically centred.
- **Ball:** a single white (`#FFFFFF`) pixel.

**Gameplay**
- While the **UP** button is held the paddle moves up 1 pixel per frame; while **DOWN** is held it
  moves down 1 pixel per frame. It always stays fully inside rows 1–47 (it never enters the score
  row and never leaves the screen).
- The ball starts in the middle of the screen and moves diagonally, 1 pixel per frame on each axis.
  It bounces off the top of the playfield (row 1 — it never enters the score row), the bottom row
  (row 47) and the right edge (column 63).
- When the ball is about to move into the paddle's column and the paddle covers the ball's row, the
  ball bounces back to the right and the **score increases by 1**.
- If the paddle is not there, the ball flies past it. When it leaves the screen on the left, the game
  is over and **resets immediately**: score back to 0 and the ball is relaunched from the middle of
  the screen. Play then continues.

Buttons are supplied with `--input` (see the docs). Save the program as `solutions/T3.vsa`. It must
run with e.g.

```
bin/vesper run solutions/T3.vsa --frames 600 --input keys.txt --out out/T3
```

and print `OK 600 frames`. We will play-test it with our own key sequences, so try several input
files yourself and check the frames before you say you're done.
